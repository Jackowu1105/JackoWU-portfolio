## Research & Discovery

Due to a tight timeline, research focused on **stakeholder interviews** to understand business goals, **competitive analysis** of 3 major food delivery apps (Uber Eats, Deliveroo, foodpanda), and proto-personas based on stakeholder insights.

### Key Insights

- Users prioritize speed and transparency — they want to browse menus quickly and know exactly when to pick up orders
- Restaurants need simplicity — owners want a straightforward interface without technical complexity
- Real-time communication is critical for both sides

## Design Process

### Information Architecture

Mapped dual-sided user flows:

**User App:** Browse Restaurants → View Menu → Customize Order → Place Order → Receive Notification → Pick Up

**Merchant App:** Receive Order → Update Status (Preparing → Ready) → Notify User

### Key Design Decisions

**Real-time Status Updates:** Designed a 3-stage progress indicator ("Order Received" → "Preparing" → "Ready for Pickup") with push notifications at each stage — borrowed from package tracking UX to set clear expectations.

**Merchant-friendly Interface:** Large, tappable buttons ("Mark as Preparing", "Mark as Ready") with single-tap status update. Owners can update orders in under 3 seconds.

**Simplified Checkout:** Kept registration lightweight with minimal fields to reduce friction and encourage signups.

## Visual Design

**Color Palette:** Warm orange (#FF6B35) for food and friendliness, dark grey (#333333) for professional readability, green (#4CAF50) for success states.

**Typography:** Poppins for headings (friendly, modern), Inter for body (highly readable on mobile).

Created a shared Figma component library ensuring consistency across user app, merchant app, and registration website.

## Impact

**15 restaurants onboarded** within 2 months of launch. Order placement time reduced from ~5 minutes (phone) to ~2 minutes (app). **85% task success rate** in usability testing — 8/10 users completed orders independently.

## Reflections

This project taught me how to design for two distinct user groups while maintaining a cohesive experience. Balancing simplicity for consumers with sufficient control for merchants required prioritizing core features first and planning for power-user features later. Real-time communication proved critical for user trust.
