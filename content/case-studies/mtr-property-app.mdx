## Research & Insights

I conducted **stakeholder interviews** with MTR estate managers across all 28 estates, **user interviews** with 15 residents from 5 different estates, **competitive analysis** of property management apps, and **contextual inquiry** observing how residents accessed estate information.

### Key Findings

- **Identity matters:** Residents feel strong attachment to their specific estate and want visual differentiation
- **Consistency is crucial:** Core navigation and features must remain predictable even with customization
- **Multi-estate users exist:** ~12% of residents manage accounts for multiple properties
- **Mobile-first behavior:** 85% of residents prefer mobile apps over websites for quick tasks

## Design Process

### Information Architecture

I defined a flexible IA that separates **universal features** (maintenance requests, facility booking) from **estate-specific content** (local events, notices), allowing content modules to be dynamically loaded based on the user's estate.

### Wireframing & Iteration

**V1** — Single static home page. Feedback: "Feels generic, doesn't reflect my estate."

**V2** — Manual estate selection at launch. Feedback: "Extra step is annoying."

**V3** — Auto-detected estate with dynamic UI. Feedback: "Feels like it's made for my community!" ✅

### Key Design Decisions

**Dynamic Color Theme System:** Created a theming system with 28 color palettes mapped to estate IDs. The app fetches the appropriate palette on login and applies it to UI components. Required rigorous color contrast testing to ensure WCAG 2.1 AA compliance across all themes.

**Seamless Estate Switching:** Designed a switcher in the profile menu that instantly changes the UI theme and content without re-authentication. Usability testing showed 90% task completion rate for multi-estate users.

## Visual Design

### Design System

Created a flexible component library in Adobe XD featuring **28 color themes** (each estate's brand colors), responsive grid system for iOS/Android, reusable UI components (buttons, cards, forms), and a typography system ensuring readability across themes. Extended the design system to responsive website, print leaflets, and backend admin UI.

### Accessibility

WCAG 2.1 AA compliance for color contrast across all 28 themes, touch targets minimum 44x44pt, and screen reader support for visually impaired residents.

## Reflections

Personalization doesn't have to mean complexity — dynamic UI can enhance UX without overwhelming users if the system is well-architected. Designing for edge cases early is crucial; multi-estate users were a minority but had the most critical pain points. Accessibility testing is non-negotiable — with 28 color themes, rigorous contrast testing was essential to avoid excluding users.
