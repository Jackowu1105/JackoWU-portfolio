## Research & Discovery

I conducted **contextual inquiry** observing airport staff during peak operational hours, **user interviews (n=12)** with operations managers and cargo coordinators, **data analysis** of AS2 usage logs to identify most-used features, and **competitive analysis** of dashboard solutions.

### Key Insights

- Different airports have vastly different priorities — small regional airports focus on cargo tracking, while large hubs prioritize OTP and bay optimization
- Users need at-a-glance status awareness — 85% check the dashboard every 10-15 minutes
- The current system required 7 clicks to access cargo tracking data

## Design Process

### Information Architecture

I restructured the dashboard around a **modular widget system**: Core Widgets (Cargo Tracking, Gate Info, OTP, Pass Rate, Bay Insight, Custom Alerts), Flexible Hierarchy (users can resize and reposition widgets), Reduced Navigation Depth (from 3-level menu to 1-click widget access).

### Wireframing & Iteration

**Low-Fidelity** — Sketched 5 different layout concepts. A rigid grid felt too restrictive, so I pivoted to a drag-and-drop flexible grid.

**Mid-Fidelity** — Tested widget customization flow with 8 users. Key insight: users wanted preset templates for common airport types to avoid starting from scratch.

**High-Fidelity** — Finalized visual design, built scalable component library, refined micro-interactions like drag-and-drop feedback and alert animations.

### Key Design Decisions

**Drag-and-Drop Widget System:** No single layout works for all airports. Implemented a 12-column grid system with flexible widget sizing. Mitigated complexity with an onboarding tour and 5 preset templates.

**Separated View and Edit Modes:** Users feared accidentally moving widgets during daily operations. Clear toggle between "View Mode" (locked layout) and "Edit Mode" (customizable). Zero accidental edits in usability testing.

**Color-Coded Status Indicators:** Red (critical), yellow (warning), green (normal) with WCAG AA-compliant contrast ratios. Usability testing showed 90% faster anomaly detection compared to AS2.

### Usability Testing

**Round 1 (Mid-Fidelity, n=8):** 75% success rate customizing dashboard. Users struggled to find "Add Widget" — made the button more prominent with "+" icons in empty grid spaces.

**Round 2 (High-Fidelity, n=10):** 95% success rate rearranging widgets and setting up alerts. Average completion time: 3 minutes (down from 7 minutes). SUS Score: 78 (vs. 52 in AS2).

## Visual Design

**Color Palette:** Primary Blue (#0066CC) for trust and reliability (aviation industry standard). High-contrast status colors tested for color-blind accessibility with Stark.

**Iconography:** Custom icon set on a 24px grid with consistent 2px strokes, optimized for small sizes in widget headers.

**Accessibility:** WCAG AA compliance (4.5:1 contrast ratio), full keyboard support for drag-and-drop, screen reader support, optimized for large control room displays (1920x1080+).

## Reflections

Balancing flexibility with simplicity was the key challenge — while power users loved deep customization, some felt overwhelmed. Preset templates proved crucial as users wanted starting points, not just a blank canvas. Performance at scale needed attention: airports with 20+ widgets experienced slight lag, requiring lazy loading optimization.
