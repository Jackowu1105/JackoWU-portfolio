## Problem Definition

Controllers mentally categorize flights by aircraft size first, as it determines resource allocation. However, the existing interface required multiple clicks to access this information, slowing down decision-making during peak hours.

### Success Metrics

- Reduce clicks required to access flight details
- Improve task completion time for identifying flight configurations
- Decrease error rate in stand assignment

## Design Process

### Information Architecture

I explored three approaches for organizing flight information:

- **Bay Type → Body Type:** Matches physical layout but conflicts with controllers' mental model
- **Flat view (all info visible):** No clicking needed but creates visual clutter
- **Body Type → Bay Type:** Aligns with controller workflow, requires one click for bay details ✅

### Key Design Decisions

**Icon System for Body Types (Collapsed View):** Wide-body and Narrow-body icons allow instant recognition without reading text. Controllers can process the entire dashboard in seconds.

**Color-Coded Bay Type Indicators:** Color dots differentiate Remote vs. Frontal stands. Applied pre-attentive processing principles for rapid recognition.

**Tab Separation in Baseline Settings:** Separate tabs for Wide-body and Narrow-body baselines in the settings page, reducing cognitive load when configuring default PTS events.

### Visual Highlights

- **Collapsed state:** Body Type icons visible for all flights — controllers scan the entire board without scrolling or clicking
- **Expanded state:** Flight details reveal Bay Type (Remote/Frontal) with color indicators
- **Settings:** Tabbed interface separates Wide-body and Narrow-body configurations with consistent color system

## Reflections

Aligning the design hierarchy with controllers' mental model (body type first) was the key to success. Using visual indicators (icons + color) for high-frequency scanning tasks dramatically improved efficiency. This project reinforced the importance of understanding user mental models before designing any information architecture.
