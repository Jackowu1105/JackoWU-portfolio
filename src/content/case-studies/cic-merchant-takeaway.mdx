## Research & Discovery

Due to a tight timeline, research focused on **stakeholder interviews** to understand business goals, **competitive analysis** of major food-delivery apps (Uber Eats, Deliveroo, foodpanda), and proto-personas based on stakeholder insights.

### Key Insights

- Users prioritise speed and transparency — they want to browse menus quickly and know exactly when to pick up orders
- Restaurants need simplicity — owners want a straightforward interface without technical complexity
- Real-time communication is critical for both sides

## Design Process

### Information Architecture

Mapped dual-sided user flows:

**User app:** Browse Restaurants → View Menu → Customise Order → Place Order → Receive Notification → Pick Up

**Merchant app:** Receive Order → Update Status (Preparing → Ready) → Notify User

### Key Design Decisions

**Real-time status updates** — A 3-stage progress indicator ("Order Received" → "Preparing" → "Ready for Pickup") with push notifications at each stage, borrowing from package-tracking UX to set clear expectations.

**Merchant-friendly interface** — Large, tappable buttons ("Mark as Preparing", "Mark as Ready") with single-tap status updates, so owners can update orders in seconds.

**Simplified checkout** — Kept registration lightweight with minimal fields to reduce friction and encourage sign-ups.

## Visual Design

### Design System

**Color:** A clean white base (`#FFFFFF`) with a vivid teal primary (`#02B3B9`) for actions and brand accent, paired with warm orange (`#EBAD7E` / `#F8B64B`) for food-related highlights and success states. The teal keeps the app feeling fresh and modern, while warm tones carry the food/friendliness cue.

A shared Figma component library ensured consistency across the user app, merchant app, and registration website.

## Outcomes & Feedback

Several restaurants were onboarded within the first couple of months. Ordering moved from a phone call to a quick in-app flow, and in usability testing most users completed orders independently.

## Reflections

This project taught me how to design for two distinct user groups while maintaining a cohesive experience. Balancing simplicity for consumers with sufficient control for merchants required prioritising core features first and planning for power-user features later. Real-time communication proved critical for user trust.
