## Design Process

### One System, Three Identities

Rather than designing three unrelated apps, I built a shared structure — the same core screens, navigation, and resident services — and layered each estate's identity on top through colour, imagery, and typography. Each estate's app reads as its own product; the shared system keeps it consistent and efficient to maintain.

### Key Design Decisions

**Estate identity over generic branding.** Residents don't think of themselves as "Hong Kong Land users" — they live in The Horizon, or Eden Manor, or Mount Verdant. The app should say the estate's name, not the developer's.

**Shared core, flexible skin.** Identical core flows (facilities, notices, service requests) with per-estate theming — the same approach as the MTR property system, refined for a premium segment.

## Visual Design

### Design System

A light, premium system: white and soft neutral surfaces (`#FFFFFF` / `#EDF0F5`) with blue-grey accents (`#D6DFE8`) and dark slate (`#454549`) for type — an understated base that lets each estate's photography and identity colours take the lead.

## Reflections

Multi-estate design is a theming problem as much as a UX one. Getting the shared core right first — before any estate's identity entered the picture — meant the visual flexibility never threatened the usability. The lesson carried forward into later property-app work: build the system, then let the brand dress it.
