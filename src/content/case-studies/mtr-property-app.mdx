## Research & Insights

I conducted **stakeholder interviews** with MTR estate managers, **user interviews** with residents from different estates, **competitive analysis** of property management apps, and **contextual inquiry** observing how residents accessed estate information.

### Key Findings

- **Identity matters** — residents feel strong attachment to their specific estate and want visual differentiation
- **Consistency is crucial** — core navigation and features must stay predictable even with customisation
- **Multi-estate users exist** — a meaningful minority of residents manage accounts for multiple properties
- **Mobile-first behaviour** — most residents prefer mobile apps over websites for quick tasks

## Design Process

### Information Architecture

I defined a flexible IA that separates **universal features** (maintenance requests, facility booking) from **estate-specific content** (local events, notices), allowing content modules to load dynamically based on the user's estate.

### Wireframing & Iteration

**V1** — Single static home page. Feedback: "Feels generic, doesn't reflect my estate."

**V2** — Manual estate selection at launch. Feedback: "Extra step is annoying."

**V3** — Auto-detected estate with dynamic UI. Feedback: "Feels like it's made for my community!" ✅

### Key Design Decisions

**Dynamic color theme system** — Created a theming system with a color palette mapped to each estate. The app fetches the appropriate palette on login and applies it to UI components. This required rigorous color-contrast testing to ensure WCAG 2.1 AA compliance across all themes.

**Seamless estate switching** — Designed a switcher in the profile menu that instantly changes the UI theme and content without re-authentication. Usability testing showed multi-estate users could switch comfortably.

## Visual Design

### Design System

A flexible component library in Adobe XD built around **per-estate color themes** — each estate's brand colors are mapped to a shared token set, so the same layout re-themes instantly without redesigning components.

**Color:** The flagship MTR estate theme uses MTR's signature red (`#AD203A`) as the primary on a clean white base (`#FFFFFF`), with each estate swapping in its own palette via the token system. Every theme is contrast-tested to hold WCAG 2.1 AA across all components.

**Typography:** A system sans-serif with a clear hierarchy that stays readable when the accent color changes between estates.

The design system was extended beyond the app to a responsive website, print leaflets, and the backend admin UI — one source of truth across every touchpoint.

### Accessibility

WCAG 2.1 AA color contrast verified across every estate theme, a minimum tap-target size, and screen-reader support for visually impaired residents.

## Outcomes & Feedback

The theming system let every estate feel like its own app while sharing one consistent core — residents recognised their estate instantly, and multi-estate users could switch without friction.

## Reflections

Personalisation doesn't have to mean complexity — dynamic UI can enhance UX without overwhelming users if the system is well-architected. Designing for edge cases early is crucial; multi-estate users were a minority but had the most critical pain points. Accessibility testing is non-negotiable — with many color themes, rigorous contrast testing was essential to avoid excluding users.
