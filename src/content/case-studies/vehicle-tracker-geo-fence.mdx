The platform is a monitoring tool first and an interface second, so I started by watching how apron teams actually work before drawing any screen. ## Research & Insights

I conducted user interviews with apron dispatchers and ground supervisors, and observed control-room operations during peak hours to understand workflow patterns.

### Key Findings

- **Information overload** — dispatchers need to focus on specific zones during critical operations, not all vehicles at once
- **Mobile vs. desktop usage** — supervisors need mobile access on-site, while dispatchers prefer large-screen monitors
- **Customisation is critical** — different shifts monitor different zones, so pre-defined zones don't match real operational needs
- **Alert fatigue** — too many notifications reduce effectiveness; the system needed smart filtering and priority-based alerts

## Design Process

### Information Architecture

Structured the interface into three core layers: **Map View** (primary workspace for vehicle tracking), **Filter Panel** (contextual control to reduce visual clutter), and **Alert System** (exception handling for urgent situations).

### Key Design Decisions

**Custom GEO fences** — Enabled users to draw and save their own GEO fences directly on the map, empowering dispatchers to adapt to changing operations without depending on IT.

**Filter-first approach** — A persistent filter panel lets users quickly toggle visibility by vehicle type, status, or custom zone — reducing cognitive load and speeding up decisions.

**Platform-specific design** — A web dashboard for multi-vehicle monitoring with analytics, and a mobile app focused on single-vehicle tracking, quick status updates, and on-site notifications.

## Visual Design

### Design System

Color-coded status indicators (Active, Idle, Offline, Alert), map-interaction patterns (zoom, pan, polygon drawing tools), filter controls (multi-select chips, quick-toggle buttons), and priority-based alert banners.

**Color:** A light, airy base (`#F1F8F6` / `#DAEBE9`) so the map and vehicle markers stay prominent, with a deep teal (`#2C677A` / `#346F80`) as the primary for controls and active states. Vehicle status uses semantic colors paired with icons so color-blind dispatchers can still tell states apart.

**Typography:** A system sans-serif with a clear hierarchy — dense data labels stay readable while vehicle IDs and alerts stay scannable at a glance.

### Accessibility

High-contrast colors for outdoor mobile use in sunlight, generous touch targets for gloved use, status indicators that use both color and icons for color-blind users, and a dark mode for night-shift dispatchers.

## Outcomes & Feedback

The platform gave dispatchers real-time visibility of apron vehicles instead of relying on radio and manual tracking, and let each shift focus on the zones and vehicle types that mattered to its operation.

## Reflections

Context matters deeply in B2B tools — spending time observing users in their actual work environment revealed pain points that interviews alone wouldn't uncover. Customisation doesn't have to mean complexity if the interface is designed thoughtfully. Platform-specific design is crucial — don't just shrink the desktop UI for mobile; rethink the use case entirely.
