## UX Research

The redesign started from a research question, not a layout question: who actually uses this dashboard, and why does one fixed layout fail them all? I ran a Double Diamond — observing airport staff in context, defining the shared failure modes, developing a configurable structure, and delivering it against real usage data.

## Research & Discovery

I conducted **contextual inquiry** observing airport staff during peak operational hours, **user interviews** with 12 operations managers and cargo coordinators, **data analysis** of AS2 usage logs to identify the most-used features, and **competitive analysis** of dashboard solutions.

### Key Insights

- Different airports have vastly different priorities — small regional airports focus on cargo tracking, while large hubs prioritise on-time performance and bay optimisation
- Users need at-a-glance status awareness — the dashboard is checked frequently throughout a shift
- The current system buried frequently-needed data behind several clicks

### User Personas

**Operations Manager Oliver (42)** — monitors overall airport performance and quickly identifies issues. Needs a high-level, customisable dashboard with KPIs at a glance.

**Cargo Coordinator Clara (35)** — manages cargo logistics and ground staff coordination. Needs detailed cargo tracking and real-time updates.

## Design Process

### Information Architecture

I restructured the dashboard around a **modular widget system**: core widgets (Cargo Tracking, Gate Info, OTP, Pass Rate, Bay Insight, Custom Alerts), a flexible hierarchy (users can resize and reposition widgets), and reduced navigation depth (from a multi-level menu to one-click widget access).

**Decision 1 — Widget system vs. fixed layout.**

### Usability Testing

**Round 1 (mid-fidelity)** — Users struggled to find "Add Widget," so I made the action more prominent with "+" icons in empty grid spaces. Success rate improved.

**Round 2 (high-fidelity)** — Users could rearrange widgets and set up alerts comfortably; completion time fell markedly from the first round, and the System Usability Scale (SUS) score rose notably versus the old AS2 system.

## Visual Design

An airport logistics dashboard is monitored for long stretches, so the interface takes a **light base with teal accents** — a clean enterprise direction that avoids saturated blue and lets teal and warm status dots carry the information hierarchy.

### Color

- **Background:** light grey-white (`#F2F3F3` / `#FEFEFE`) — keeps data widgets and status colors prominent
- **Primary:** teal (`#61DBB7` / `#2EA7A9` / `#7ABEBF`) — used for emphasis, data highlights, and active widgets
- **Status / accents:** warm yellow (`#FFDF91`) for alerts and secondary highlights; red/yellow/green status colors flag anomalies at WCAG AA contrast
- A dedicated **Color Style** spec page unifies the palette across the product

### Iconography

A custom icon set on a 24px grid with consistent 2px strokes, tuned for the small sizes used in widget headers so controllers can recognise them inside dense widgets.

### Accessibility

WCAG AA (4.5:1 contrast), full keyboard support for drag-and-drop, screen-reader support, and optimisation for large control-room displays.

## Outcomes & Feedback

The redesigned dashboard let each airport configure its own workspace instead of forcing one rigid layout — users could surface the data that mattered to their operation, and anomaly detection became faster at a glance.

## Reflections

Balancing flexibility with simplicity was the key challenge — while power users loved deep customisation, some felt overwhelmed. Preset templates proved crucial as users wanted starting points, not just a blank canvas. Performance at scale needed attention: airports with many widgets experienced lag, requiring lazy-loading optimisation.
